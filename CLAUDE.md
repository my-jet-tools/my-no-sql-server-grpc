# my-no-sql-server-grpc

**Прочти [DESIGN.md](DESIGN.md) прежде чем что-либо менять.** Там принятые
решения с обоснованиями, что уже сделано и что осталось. Многое из этого не
выводится из кода — например, почему `TimeStamp` и `Expires` не лежат в сырье
строки, и почему у ридера нет подтверждений доставки.

MyNoSqlServer, у которого сущности protobuf, а не JSON. Здесь только `server/`
и `proto/` — контракты, которые компилируются на месте. Ядро, контракт сущности,
макрос и оба клиента переехали в SDK — `../my-no-sql-grpc-sdk`, он же
`github.com/my-jet-tools/my-no-sql-grpc-sdk` — и сервер тянет их **по тегу**, те
же крейты, которые берёт приложение. Правка ядра поэтому означает коммит и тег
там, потом бамп тега в `Cargo.toml` здесь.

Веб-интерфейс — Dioxus-SPA в `ui/`, крейт вне воркспейса: собирается `dx` под
wasm (`./build-ui.sh`), результат кладётся в `wwwroot/`, который коммитится и
запекается в образ. Правил UI — пересобери и закоммить `wwwroot/`, иначе сервер
отдаёт прежнюю сборку.

Сервер сам отдаёт MCP на `/mcp` (порт 5123) — `server/src/mcp/`. Его записи
закрыты, пока человек не позовёт `POST /api/Mcp/Writes?enabled=true`; окно на 10
минут, и это единственный способ его открыть — тула для этого нет намеренно.

Эталон по функционалу — JSON-версия, она лежит рядом:
`../MyNoSqlServer/my-no-sql-server` (сервер) и `../MyNoSqlServer/my-no-sql-sdk`
(ядро и клиенты). Список того, что до неё ещё не сделано, — в конце DESIGN.md.

## Правила

- перед изменением заведомо покрытой области подтяни гайд из MCP
  `development-best-practices` (gRPC, my-json, персист, бутстрап) — память по
  API MyJetTools врать будет;
- `cargo test`, `cargo clippy --all-targets -- -D warnings` и `cargo fmt --all`
  обязаны оставаться зелёными; `#[allow(clippy::...)]` не решение — правь причину;
- если дописал контракт в proto, но породить его пока некому — не оставляй
  мёртвых веток в Rust, добавляй вместе с операцией, которая их порождает;
- проверяй живьём, а не только тестами: сборка ломалась ровно там, где тесты
  проходили (пропавшая скобка JSON-массива нашлась первым `curl`). Для контрактов
  есть два уровня: `server/src/sdk_tests.rs` поднимает настоящий сервер на сокете
  и гоняет оба клиента (они приходят фасадом `my-no-sql-grpc-sdk` в dev-зависимостях),
  а пример `cargo run --example round_trip --all-features` в репозитории SDK делает
  то же против сервера в отдельном процессе;
- `proto/` живёт здесь, а в SDK лежит его копия — поменял контракт, обнови её там
  же, иначе это поймает шаг CI «Contract is in sync» в SDK, а не компилятор.
